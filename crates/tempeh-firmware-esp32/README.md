# ESP32 Firmware

Firmware for the ESP32-S3-DevKitC-1.

Reads DS18B20 waterproof probes on separate GPIO pins, prints labelled temperature readings over USB serial, and runs the shared real-run control policy on device.

This firmware does not actuate the heater yet. It reports the heater decision it would make as `control,...` rows and applies those decisions to a dry-run heater output.

## Protocol

```text
temp,box_air,22.437
temp,room_air,20.125
temp,product,23.125
```

It also emits control-policy samples once box_air has been seen:

```text
control,time_s,room_air_temp_c,box_air_temp_c,product_temp_c,heater_on,reason
control,1,,22.437,23.125,1,below_target
```

The `control,...` rows are generated by `tempeh-runtime::RealRunController`.

When the dry-run heater output changes state, firmware also emits:

```text
heater,dry_run,on,below_target
heater,dry_run,off,box_air_stale
```

These rows are diagnostic only. No physical heater is switched by this firmware yet.

## Pins

```text
GPIO5 -> box_air DATA
GPIO6 -> room_air DATA
GPIO4 -> product DATA
3V3   -> probe adapter VCC
G     -> probe adapter GND / BLK
```

## Setup

Install the ESP Rust tools:

```bash
cargo install espup
espup install
cargo install espflash
```

Load the ESP environment:

```bash
. ~/export-esp.sh
```

## Flash

The firmware connects to Wi-Fi on boot. Create a local firmware config file:

```bash
cp firmware.local.example.toml firmware.local.toml
```

Then edit:

```toml
[wifi]
ssid = "your-wifi-name"
password = "your-wifi-password"

[tasmota]
base_url = "http://192.0.2.10"
```

`firmware.local.toml` is ignored by Git. Do not commit real Wi-Fi credentials.

Then flash from this directory:

```bash
ESPFLASH_PORT=/dev/cu.usbmodem1234561 cargo run --release
```

The firmware sends a boot-time Power Off command to the configured Tasmota plug. It does not yet apply runtime heater decisions to the plug.

Expected boot log includes:

```text
Wi-Fi connected: ip=...
sending Tasmota heater off command: reason=boot_safe_off
Tasmota heater command accepted: heater_on=false
```

After flashing, run the host-side smoke test from the repository root:

```bash
cargo run -p tempeh-host -- thermometer-test /dev/cu.usbmodem1234561
```

For a supervised heat-mat control run from the repository root:

```bash
cargo run -p tempeh-host -- real-control-test /dev/cu.usbmodem1234561 http://192.0.2.10 out/heat-mat-empty-box-01.csv
```

Expected host output:

```text
time_s,room_air_temp_c,box_air_temp_c,product_temp_c
1,20.125,22.437,23.125
```

The product_temp_c column remains blank until the product probe has emitted at least one valid reading.

The firmware-side `control,...` and `heater,dry_run,...` rows are diagnostic only until a real heater adapter is added.

The firmware also runs a periodic safety tick after every probe sweep. This lets stale-reading safety turn the dry-run heater off even if no new probe reading successfully updates the control policy.
